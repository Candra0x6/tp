# TRUST FALL

A virtual handheld console, **BLOCKBOY**, running one cartridge: **TRUST FALL**.
A party of 2 to 4 climbs a tower. Each floor has N doors and exactly one is safe.
Every player is privately dealt a clue that only they can read. No clue solves a
floor alone. All the clues together solve it exactly. To climb, you have to talk.

Built for **MagicBlock Blitz v7**, theme **collaboration**.

**Read `docs/PRD.md` before any product, feature, copy, or scope decision.**
This file holds only what must be true in every session.

## Non-negotiable rules

1. **The clues are never generated by a model.** They are a deterministic
   function of VRF randomness, computed onchain. See `docs/technical/GAME-LOGIC.md`.
2. **Never claim more privacy than the deployment gives.** On a public ER every
   account is readable by RPC, so the game is cheatable. Only the Private ER
   makes it real. Whichever is deployed, the README and the screen say which.
3. **Never show a payout the vault cannot pay.** Every offer is clamped to the
   live vault balance, and the balance is on screen.
4. **Rake is zero.** Money comes from parties that fell, and from the seed. There
   is no third source and the UI says so in words.
5. **Request acceptance is not fulfilment.** VRF requests, crank schedules, and
   commits are all asynchronous. Every one of them gets a visible pending state
   and a timeout, never an optimistic render.
6. **The party is 2 to 4 and always full.** Empty seats are filled by CPU players
   labelled `CPU` on screen. Never let a judge sit in an empty lobby.
7. **No em-dashes in user-facing copy.**
8. **Names are tokens, never literals.** Every product name lives only in
   `components/config/brand.ts`. A rename is a one line edit.
9. **`docs/technical/BUILD-PLAN.md` is updated in the same commit as the work.**
   Task finished, gate passed or failed, scope cut, question answered: flip the
   cell now. A build plan that lags the repo gets believed, which is worse than
   not having one.
10. **Never hardcode the ER endpoint.** Get the `fqdn` from router
    `getDelegationStatus` for the account. The region that answers today is not
    guaranteed to answer on Sunday.

## The fixed grid

The game renders on a **fixed logical grid of 480 x 320**. Everything snaps to
**4px**. Base type is an **8px bitmap font** (Departure Mono). Sprites are
authored at **16x16** and **32x32** and scale by **integer factors only**.
`image-rendering: pixelated` on every sprite, always. **DOM and CSS, no canvas
engine.**

The shell is black with the MagicBlock mark. The screen inside it is its own
palette, **LANTERN**, and does not borrow the hackathon website's colours.

One block per screen absorbs the vertical remainder with `flex-1 min-h-0` plus a
`minHeight` floor. Fixed blocks keep their natural size. Never budget a screen
by hand-summing line heights, that arithmetic is always optimistic and
`overflow: hidden` never warns.

## Self Learning Logs

Root cause plus the durable rule. Newest on top. One short entry each.

### 2026-08-05 - Hiding the clues is the same act as hiding the answer

- **Cause:** The first architecture had a `FloorSecret` account holding the safe
  door, plus separate private clue accounts, as if they were two problems.
- **Rule:** The safe door is exactly the door no clue eliminates, so anyone who
  can read every clue already knows the answer. There is one secret, not two.
  Per-player clue privacy is the whole security model, and on a public ER, where
  any RPC client can read any account, there is no security model at all.

### 2026-08-05 - A vote is not collaboration unless players hold different facts

- **Cause:** The first draft of the tower let the party vote on a door whose
  safety was pure VRF. Everyone knew the same thing, which is nothing, so the
  vote carried no information and the collaboration theme was decoration.
- **Rule:** Coordination mechanics require asymmetric information by
  construction. If every player can compute the same answer from the same state,
  delete the vote, it is a formality. The clue deal exists to make the vote real.

### 2026-08-05 - Perfect play with no clock makes the economy meaningless

- **Cause:** With unlimited time, full clue sharing clears every floor, so risk
  is zero, so banking is never correct, so the pot, the multiplier, and the
  bank-or-climb vote were all theatre.
- **Rule:** The scarce resource is time, not information. The floor timer is what
  makes banking a real decision, and it makes the risk a test of the team rather
  than a dice roll. Any change that relaxes the clock has to re-answer "why would
  anyone ever bank".

## Self Insight Logs

Observation plus how to apply. Newest on top. One short entry each.

### 2026-08-05 - Wants the MagicBlock brand on the hardware, not in the game

- **Observed:** "yang penting di game console nya itu black aja sama ada magic
  block logonya terus itu game screen nya background dll gausa ikutin yang
  hackathon website nya."
- **Apply:** Sponsor identity belongs on the shell, which is the frame. The
  screen is the product and gets a palette chosen for legibility and mood. Never
  paste a sponsor's marketing palette into a game surface.

### 2026-08-05 - Asks where a number comes from before accepting it

- **Observed:** Asked directly how clues get generated, how many doors per floor,
  and where the prize money comes from, before agreeing to anything.
- **Apply:** For every number the product shows, be able to name the whole chain
  from input to pixel. Say "from parties that fell" out loud rather than letting
  a multiplier imply free money.

### 2026-08-05 - Reviews rendered pixels, from a phone

- **Observed:** On the previous project, caught invisible footer buttons, caption
  spacing, and unchosen indents from a phone screenshot, all in one message.
- **Apply:** Never report a layout as done without saying whether it was actually
  seen rendered. Check at 412px before calling it finished.
